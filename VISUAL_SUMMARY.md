│ export ANTHROPIC_API_KEY=sk-ant-...     │ ← Your Claude access

│ export CEX_TOOL=.../...py               │ ← Main script
│ export CLAUDE_MODEL=claude-3-5-...      │ ← Which Claude

│ alias cex-analyze=python .../...py ...  │ ← Shortcut

## **🔀 DATA FLOW: From Certora to Claude to Your Code**

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. CERTORA PROVER RUNS (Cloud or Local)                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ Your Contract Code + CVL Specification                          │
│         │                                                       │
│         ↓                                                       │
│ [Certora Symbolic Engine]                                       │
│ • Analyzes all paths                                            │
│ • Finds violations                                              │
│ • Generates counterexamples                                     │
│         │                                                       │
│         ↓                                                       │
│ Results downloaded to /tmp/certoraOutput/                       │
│ ├─ treeViewStatus_1.json (rule results)                         │
│ └─ callTrace_1.json (counterexamples)                           │
└────────────────────┬──────────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────────────────────┐
│ 2. YOUR TOOL EXTRACTS CEX                                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ $ cex-analyze ./prover_results rule_name                        │
│         │                                                       │
│         ↓                                                       │
│ [extract_and_analyze_cex.py]                                    │
│ • Parses JSON files                                             │
│ • Extracts counterexample                                       │
│ • Formats nicely                                                │
│         │                                                       │
│         ↓                                                       │
│ Formatted CEX (tree structure)                                  │
│ ├─ Function calls                                               │
│ ├─ State changes                                                │
│ └─ Assertion failures                                           │
└────────────────────┬──────────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────────────────────┐
│ 3. CLAUDE AI ANALYZES                                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ [Claude API]                                                    │
│ Input:                                                          │
│ • CEX (what triggered the violation)                            │
│ • CVL Spec (what should happen)                                 │
│ • Your code (what's wrong)                                      │
│         │                                                       │
│         ↓                                                       │
│ Claude Reasoning:                                               │
│ • "I see transfer() doesn't check balance..."                   │
│ • "Root cause: missing require statement"                       │
│ • "Fix: add require(balance >= amount)"                         │
│         │                                                       │
│         ↓                                                       │
│ Response (markdown):                                            │
│ ├─ Scenario description                                         │
│ ├─ Root cause analysis                                          │
│ ├─ 2-3 specific code fixes                                      │
│ └─ Confidence level                                             │
└────────────────────┬──────────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────────────────────┐
│ 4. YOU APPLY THE FIX                                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ $ vim contracts/Token.sol                                       │
│                                                                 │
│ Before:                          After:                         │
│ function transfer(...) {         function transfer(...) {       │
│   balances[to] += amount;        require(...);                  │
│ }                                balances[to] += amount;        │
│                                  }                              │
│                                                                 │
│ (Based on Claude's suggestion)                                  │
└────────────────────┬──────────────────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────────────────────┐
│ 5. RE-VERIFY (Loop back to step 1)                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│ $ certoraRun config.conf --output_dir ./prover_results_v2       │
│         │                                                       │
│         ↓                                                       │
│ Check: $ cex-list ./prover_results_v2                           │
│                                                                 │
│ If still VIOLATED → Analyze next failure                        │
│ If all VERIFIED → ✅ YOU'RE DONE!                               │
└────────────────────────────────────────────────────────────────┘
```
